1. Introduction

This part of my learning journey focuses on automating the installation of a Debian VM using the preseeded configuration file.

Here, we describe how to install Debian GNU/Linux (13.x, netinst ISO) into a bhyve VM on a FreeBSD host without answering any installer prompts. It uses Debian’s preseed mechanism: all installer answers live in a preseed.cfg file that the installer downloads over HTTP from the host. The flow can be driven from a shell script, Ansible, or a Terraform local-exec provisioner. It builds on the manual procedure in FreeBSD_Bhyve_DebianVM document (vm-bhyve, private bridge bridge0, PF NAT out of wlan0).

Constants to be used for the install:

Item Value
Host bridge (gateway) 10.0.0.1 (bridge0)
VM address 10.0.0.10/24
DNS 1.1.1.1
VM name k8s-node
ISO debian-13.7.0-amd64-netinst.iso in zroot/bhyve.iso/
Preseed URL http://10.0.0.1:8000/preseed.cfg

2. Prerequisites

The preparation steps for the VM, that are listed in the FreeBSD_Bhyve_DebianVM document should be completed. These are the steps, as listed in that document:

  • Host preparation
  • Initialize the hypervisor and the networking
  • Download the Debian Netinst ISO

Also the following are required on the host:

  • A way to serve one file over HTTP on 10.0.0.1. FreeBSD base has no web server, so install one: pkg install python3 (used below) or pkg install darkhttpd.
  • An SSH key pair on the host or control machine. The public key goes into the preseed.
  • A SHA-512 password hash for the VM user: openssl passwd -6

Switch name: the VM config must reference the switch created in the manual note, which is named private, so we use network0_switch="private".

3. Step 1: Create preseed.cfg

The following content should as /root/preseed/preseed.cfg. This is available as preseed.cfg.tmpl in the repository. Replace the password hash and the SSH public key. 

### Locale / keyboard
d-i debian-installer/locale string en_US.UTF-8
d-i keyboard-configuration/xkb-keymap select us

### Network (static, matches the private bridge)
d-i netcfg/choose_interface select auto
d-i netcfg/disable_autoconfig boolean true
d-i netcfg/get_ipaddress string 10.0.0.10
d-i netcfg/get_netmask string 255.255.255.0
d-i netcfg/get_gateway string 10.0.0.1
d-i netcfg/get_nameservers string 1.1.1.1
d-i netcfg/confirm_static boolean true
d-i netcfg/get_hostname string k8s-node
d-i netcfg/get_domain string local

### Mirror
d-i mirror/country string manual
d-i mirror/http/hostname string deb.debian.org
d-i mirror/http/directory string /debian
d-i mirror/http/proxy string

### Accounts (no root login; one sudo user)
d-i passwd/root-login boolean false
d-i passwd/user-fullname string Ops User
d-i passwd/username string ops
d-i passwd/user-password-crypted password $6$REPLACE_WITH_HASH

### Clock
d-i clock-setup/utc boolean true
d-i time/zone string Asia/Kolkata
d-i clock-setup/ntp boolean true

### Partitioning: whole disk, single partition
d-i partman-auto/method string regular
d-i partman-auto/choose_recipe select atomic
d-i partman-partitioning/confirm_write_new_label boolean true
d-i partman/choose_partition select finish
d-i partman/confirm boolean true
d-i partman/confirm_nooverwrite boolean true

### Packages
tasksel tasksel/first multiselect standard, ssh-server
d-i pkgsel/include string sudo curl
d-i pkgsel/upgrade select none
popularity-contest popularity-contest/participate boolean false

### Bootloader
d-i grub-installer/only_debian boolean true
d-i grub-installer/bootdev string /dev/vda
### Inject SSH key for Ansible / remote access
d-i preseed/late_command string \
    in-target mkdir -p /home/ops/.ssh ; \
    in-target sh -c 'echo "ssh-ed25519 AAAA...your-public-key..." > /home/ops/.ssh/authorized_keys' ; \
    in-target chown -R ops:ops /home/ops/.ssh ; \
    in-target chmod 700 /home/ops/.ssh ; \
    in-target chmod 600 /home/ops/.ssh/authorized_keys

### Power off when finished so automation can detect completion
d-i debian-installer/exit/poweroff boolean true
d-i finish-install/reboot_in_progress note

About sudo: pkgsel/include installs sudo explicitly. With passwd/root-login false, the installer also installs sudo and adds the first user to the sudo group. This gives sudo with a password prompt.

Optional: passwordless sudo for automation

If Ansible connects as this user and uses become, either supply ansible_become_password or allow passwordless sudo. For the latter, insert these two lines into late_command, before the final chmod 600 line (keep the trailing backslashes on every line except the last one of the block): 

in-target sh -c 'echo "ops ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/ops' ; \
in-target chmod 440 /etc/sudoers.d/ops ; \

This is a security trade-off; decide whether it suits a VM that will run a Kubernetes node.

4. Step 2: Create and configure the VM

vm create -t linux -s 40G k8s-node
vm configure k8s-node

The configuration should contain the following: 

loader="grub"
cpu=2
memory=2G
network0_type="virtio-net"
network0_switch="private"
disk0_type="virtio-blk"
disk0_name="disk0.img"
grub_install0="linux /install.amd/vmlinuz auto=true priority=critical url=http://10.0.0.1:8000/preseed.cfg netcfg/disable_autoconfig=true netcfg/get_ipaddress=10.0.0.10 netcfg/get_netmask=255.255.255.0 netcfg/get_gateway=10.0.0.1 netcfg/get_nameservers=1.1.1.1 netcfg/get_hostname=k8s-node netcfg/get_domain=local console=ttyS0,115200n8 --- console=ttyS0,115200n8; initrd /install.amd/initrd.gz"

The network values are repeated on the kernel command line because the installer must bring the network up before it can download the preseed file. The private bridge has no DHCP server, so without them the installer would wait for autoconfiguration.

5. Step 3: Serve the preseed file

cd /root/preseed
python3 -m http.server 8000 --bind 10.0.0.1

Alternative with darkhttpd: 

darkhttpd /root/preseed --addr 10.0.0.1 --port 8000

Leave the server running for the duration of the install.

6. Step 4: Run the install

Without -f, vm install starts the VM in the background and returns immediately. Because the preseed powers the VM off when finished, a script can poll the VM state to detect completion.

Shell script (/root/provision-k8s-node.sh): 

#!/bin/sh
set -e

python3 -m http.server 8000 --bind 10.0.0.1 --directory /root/preseed &
HTTP_PID=$!

vm install k8s-node debian-13.7.0-amd64-netinst.iso

# Wait for the installer to power the VM off
while vm list | grep -q "k8s-node.*Running"; do
    sleep 10
done

kill $HTTP_PID
vm start k8s-node

To watch progress, attach to the serial console from another terminal: vm console k8s-node (detach with ~.).

7. Step 5: Verify

ping -c 3 10.0.0.10
ssh ops@10.0.0.10 'id; dpkg -l sudo; hostnamectl'

Expected: the VM answers on 10.0.0.10, the ops user belongs to the sudo group, and the sudo package is installed.

8. Notes and troubleshooting

  • Installer stalls at network configuration: check that network0switch matches the real switch name (vm switch list) and that the netcfg/* arguments are present on the kernel line.
  • Preseed not fetched: from the host, confirm fetch -o - http://10.0.0.1:8000/preseed.cfg works, and that PF is not blocking port 8000 on bridge0 (the sample pf.conf skips filtering on bridge0).
  • Preseed keys change between releases: compare against the example preseed for your release at https://www.debian.org/releases/stable/amd64/apb.en.html.
  • Re-running: destroy the VM first (vm destroy k8s-node) or recreate its disk, otherwise the installer will find existing partitions.
  • Boot after install: with loader="grub", vm-bhyve boots the installed system through grub-bhyve. If the VM does not boot after the install, check the vm-bhyve documentation for the grubrun0 setting.
